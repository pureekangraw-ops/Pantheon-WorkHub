# Pantheon WorkHub — Existing primary Worker (preview capability)

## Provisioned in Cloudflare

- Worker: `phatheon-workhub` (the existing original Worker, upgraded in place).
- Base URL: `https://phatheon-workhub.pureekangraw.workers.dev/`.
- D1: `pantheon-workhub` (primary database; UUID `22b59dc3-e07c-4ae7-b5b1-2646d3e8a975`).
- `WORKHUB_TOKEN`: an encrypted secret binding; its value is never committed to the repository.
- The previous original Hello-world Worker code is saved in `cloud/backups/phatheon-workhub-before-migration.js` for rollback. Other Workers remain unchanged.
- Initial staging token was randomly generated by Cloudflare setup. It is not recoverable/readable through Cloudflare. The owner must **rotate it to a value they know** in Cloudflare → Workers & Pages → phatheon-workhub → Settings → Variables and Secrets before using the dashboard. Choose a high-entropy token of **at least 32 characters**, and never paste it into chat, Git, screenshots or logs.

## Supported scope

The preview page is a small authenticated owner dashboard. It can queue text-artifact tasks, inspect queued tasks, explicitly run the sole D1 text-artifact action, verify readback, display immutable audit events, and reconcile uncertain outcomes. The submitted instruction is stored inside D1: **do not submit secrets**.

The engine **does not** automatically run an AI model, shell command, external connector, or production task. It does not yet provide a complete workflow engine, pause/cancel acknowledgements, human approvals, rich task delegation, local AI model serving, or cloud-to-local migration.

## Local development and acceptance

Requires Node.js 22+.

```sh
cd cloud
npm install --no-save wrangler@4
npm test
npm run check

# Local-only D1; does not affect the Cloudflare database:
npx wrangler d1 execute pantheon-workhub --local --file=schema.sql
# Supply a unique local secret of at least 32 characters in cloud/.dev.vars:
printf 'WORKHUB_TOKEN=%s\n' "$(openssl rand -hex 32)" > .dev.vars
npx wrangler dev --local --ip 127.0.0.1 --port 8789
```

In a second terminal, export the exact local `WORKHUB_TOKEN` as `SMOKE_TOKEN` and run `node tests/smoke.mjs`. The GitHub cloud CI runs this sequence automatically with a temporary token and temporary D1. It also performs a public primary Worker health/authentication check.

## API

- `GET /health` public; no private data.
- `GET /` owner dashboard. Access token is kept in page memory, not browser local storage.
- `POST /v1/intent` with JSON:
  - `{"intent":"CREATE_TASK","request":"text to preserve"}` returns QUEUED, does not execute.
  - `{"intent":"SHOW_TASK","task_id":"task_..."}`
  - `{"intent":"LIST_TASKS"}`
- `POST /v1/tasks/:id/run`: owner explicitly runs the safe D1 artifact action.
- `POST /v1/tasks/:id/recover`: only after a time buffer for potentially running actions.
- `POST /v1/tasks/:id/retry`: only after verified no-effect reconciliation.
- `GET /v1/tasks/:id/events`: read audit trail.
- `GET /v1/tasks/:id/artifact`: read verified artifact only when COMPLETED.

All routes other than `/` and `/health` require `Authorization: Bearer <WORKHUB_TOKEN>`.

## Safety and release notes

- Authentication gates all task data and mutation APIs. Model JSON never authenticates users or authorizes tool execution.
- D1 task claim is conditional on QUEUED. A stable unique action key and unique D1 artifact key prevent duplicate text artifacts.
- Events reject UPDATE and DELETE in D1 triggers.
- In-flight crash recovery checks persisted artifact content before deciding completion or failed/no-effect retry.
- D1 `db.batch` is transactional; it is not a substitute for an external side-effect transaction. New tools must add separate idempotency/reconciliation guarantees.
- The UI stores the access token only in JavaScript memory. Do not use it on untrusted devices.
- GitHub Actions passing does not guarantee the deployed Cloudflare Worker has the latest commit: direct Worker upload and live verification are separate steps.
- Keep PR #2 in draft until broader production readiness, deployment release controls, long-running workers, robust auth/approval, and cloud/local migration are proven.

## Factory District: owner-triggered LOGIC trainee integration

Factory maintains the existing City/Metro HMAC key untouched. A new isolated
`PANTHEON_FACTORY_RAIL_SECRET` at Factory and `FACTORY_PANTHEON_SECRET` at
WorkHub must hold the **same newly generated key**, stored as Cloudflare secret
bindings. Neither key belongs in GitHub, Work payload, browser nor logs.
The Factory checks the `PANTHEON` signed client header and restricts it to
PANTHEON-owned scoped `WORK_PASS_V1` envelopes, `LOGIC` and
`PLACE_DWARF_LOGIC_TRAINEE`; it cannot impersonate City Hall.

Run `cloud/migrations/0002_factory_jobs.sql` **once** against existing primary
D1 before deploying the updated WorkHub. Do not drop or replace current tables.

Owner-only API (Authorization: Bearer WORKHUB_TOKEN):
- `POST /v1/factory/jobs` with `{"request":"training bench note"}` creates
  QUEUED Work with durable Work ID, but **does not execute** anything.
- `POST /v1/factory/jobs/:task_id/dispatch` explicitly claims and sends the
  immutable Work Pass via the FACTORY Service Binding. First Factory preflight
  validates scope, then Factory persists idempotency claim and runs its
  registered LOGIC trainee bench handler.
- `GET /v1/factory/jobs/:task_id` shows durable receipt and evidence readback.
- `POST /v1/factory/jobs/:task_id/reconcile` reads the saved receipt without
  resending work, or reissues the identical Work ID and Checkpoint ID when the
  original response was lost. Factory guarantees no second machine execution.

A Factory `HANDOFF_VERIFIED` receipt without verified domain evidence is not
COMPLETED. The LOGIC runner currently places `DWARF-01` at the DEVELOPMENT_BENCH
with `productionAuthority:false`; it is **not** production CODE/VISUAL
execution, AI inference, or fulfillment of arbitrary free-text instructions.
The WorkHub stores the owner note for traceability only.

The public health endpoint remains metadata-only; no private Work or secret
is surfaced. Service Binding connectivity and CI mock tests are not a substitute
for an authorized production preflight/dispatch/readback test. WorkHub
`WORKHUB_TOKEN` remains owner-only and must be rotated privately to a known
high-entropy value before interactive use.
